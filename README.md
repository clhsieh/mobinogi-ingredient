# 瑪奇 MOBILE 製作計算機

左上角可以切換兩種模式：

- **查配方（選成品）**：點選一個製作物，右側會展開所有需要的材料（含多層配方
  遞迴展開）、建議製作順序，以及估計的總製作時間。
- **查用途（選材料）**：反過來，點選任何一個材料或半成品，看它會被用來做什麼、
  一路往上展開到最終成品是什麼，不需要自己一個一個配方去對照。

這是一個純靜態網頁（HTML + CSS + JavaScript，無需 build、無需伺服器），
可以：

- 直接在本機用瀏覽器開啟 `index.html`
- 或部署到 GitHub Pages：把整個資料夾 push 到 GitHub，
  到 repo 的 Settings → Pages，選擇 branch（例如 `main`）與根目錄即可自動產生網址。

## 目前的配方資料

`data.js` 目前放的是瑪奇 MOBILE 的一部分鍛造／伐木配方，資料還不完整，

## 如何更新配方

先編輯 `recipes.csv`（用 Excel／Numbers／Google 試算表打開，新增或修改配方列），
再用底下任一種方式轉換成 `data.js`：

- **CLI（推薦，本機裝了 Node.js 的話最快）：**
  ```bash
  node tools/build.js
  ```
  會直接讀專案根目錄的 `recipes.csv`、覆蓋 `data.js`，不用手動下載/搬移檔案。
  執行時會印出轉換訊息（自動判定的原始材料、錯誤或警告）；有錯誤的話
  `data.js` 不會被覆蓋，修好 CSV 再跑一次即可。也可以指定其他路徑：
  `node tools/build.js 我的配方.csv 我的data.js`。
- **瀏覽器工具（不想用終端機的話）：** 用瀏覽器打開 `tools/convert.html`，
  匯入（或貼上）CSV 內容，按「轉換 → 產生 data.js」，再按「下載 data.js」，
  把下載的檔案覆蓋到專案根目錄的 `data.js`。

兩種工具邏輯完全一樣，轉出來的內容會一致，挑順手的用就好。

`recipes.csv` 欄位說明（**不需要另外想英文 id，直接填物品的中文名稱就好**）：
- `name`：物品名稱，同時當作唯一代碼，其他配方直接用這個名稱引用（名稱本身請
  避免包含 `:`、`;`、`,` 這幾個符號）
- `category`：大分類（自由命名，會顯示在左側第一層篩選 tab）
- `subcategory`：小分類（自由命名，選填；同一大分類下有填的話，
  會多出現第二層篩選 tab，例如「武器」下面再分「劍」「弓」）
- `craft_time_sec`：每次製作時間，可以直接寫秒數（`100`），也可以寫
  `1小時40分`、`90秒`、`2分30秒` 這種格式，會自動換算成秒數；原始材料留空
- `output_qty`：每次製作可產出幾個；原始材料留空
- `materials`：所需材料，格式 `材料名稱:數量`，多個材料用 `;` 分隔，
  例如 `鐵錠:2;木材:1`；原始材料留空

轉換工具會檢查數字欄位是否合法、`materials` 格式是否正確，有問題會直接顯示錯誤訊息。

### 不需要列出原始材料

只要某個材料名稱從來沒有出現在任何一列的 `name` 欄，就會自動被當成「直接採集」的
原始材料（例如礦石、煤炭這種買/採集來的東西），不用特地為它加一列。像這樣：

```
鋼錠,材料,金屬,600,3,鐵錠:3;煤炭:4
```

只要 `煤炭` 沒有自己的那一列，它就會自動變成原始材料，出現在計算結果的
「所需原始材料總表」裡。如果想幫原始材料指定分類/小分類，還是可以自己加一列
（`materials` 欄留空即可）。

### 同一物品可以有多種配方

有些製作物在遊戲裡不只一種做法（例如鐵錠可以用「礦石」做，也可以用「鐵礦石」做）。
只要用同一個 `name` 寫好幾列、每列填不同的 `materials` 就可以了：

```
鐵錠,材料,金屬,60,3,礦石:20
鐵錠,材料,金屬,60,3,鐵礦石:10
```

（`category`/`subcategory` 只要有一列填就好，其餘可以留空；每一列都要各自填
`craft_time_sec`、`output_qty`、`materials`。）網站會在該物品的詳細頁面顯示
「配方選擇」，讓使用者自己挑一種來計算材料與時間。

## 如何直接修改 data.js（進階）

也可以略過 CSV，直接打開 `data.js`，在 `ITEM_LIST` 陣列中新增一個物件。
可製作物的格式（`recipes` 是陣列，可以放多筆＝多種配方）：

```js
{
  id: "鐵錠",             // 直接用物品名稱當唯一代碼即可，其他配方用這個名稱引用
  name: "鐵錠",           // 顯示名稱，通常跟 id 相同
  category: "材料",        // 大分類，會顯示在左側第一層篩選 tab
  subcategory: "金屬",     // 小分類，選填；同一大分類下有填才會出現第二層篩選 tab
  recipes: [
    { craftTime: 60, outputQty: 3, materials: [{ id: "礦石", qty: 20 }] },
    { craftTime: 60, outputQty: 3, materials: [{ id: "鐵礦石", qty: 10 }] },
  ],
}
```

`craftTime` 可以直接寫秒數，也可以寫 `"1小時40分"` 這種格式。

原始材料（用採集、購買、掉落取得，無法再展開）不需要 `recipes`，只要
`id`、`name`、`category` 即可，而且**只要沒有任何配方的 `materials` 引用到它、
它本身也沒有出現在 `ITEM_LIST` 裡，也會被 app.js 自動當成原始材料**（不會報錯）：

```js
{ id: "木材", name: "木材", category: "原料" },
```

新增後存檔、重新整理網頁即可看到，不需要改 `app.js` 或 `index.html`。

## 計算邏輯說明

- 配方選擇：如果展開的配方樹中有物品存在多種配方，會在「配方選擇」區塊列出來，
  選哪一種會即時影響下面的材料樹、原始材料總表與總製作時間（同一物品在整棵樹裡
  只會用同一種配方計算）。
- 展開配方樹：從選擇的成品往下遞迴展開每一層材料，可個別收合/展開。
- 所需原始材料總表：把整棵配方樹展開後，將同一種原始材料的需求量加總，
  並考慮「一次製作可產出多個」時無條件進位到下一個製作次數。
- 總製作時間：所有需要製作的中間材料與成品，其製作次數 × 該項目製作時間的總和，
  假設依序製作、不考慮多工作站同時進行或加速道具。

## 查用途（反查材料）怎麼算的

切到「查用途」模式後，左側清單會列出**所有**項目（原始材料、半成品、成品都可以選），
選一個之後：

- 「直接用於」：掃描所有物品的所有配方（不受配方選擇影響），
  列出哪些物品的配方裡直接用到它。
- 「用途展開」：把「被誰用到」一路往上展開——如果 A 用到你選的材料，
  又有 B 用到 A，就會展開成 你選的材料 → A（配方 X）→ B（配方 Y）→ …，
  一路往上直到某個物品沒有再被任何配方用到為止（也就是最終成品），
  或偵測到循環引用時停止。
- 「最終會做出」：把整條展開路徑上所有到達的最終成品去重後的數量與名稱列出來，
  讓你一眼看到這個材料最後都流向哪些成品。

## 奇幻生活會員（製作時間）

**`recipes.csv` / `data.js` 裡填的 `craft_time_sec` / `craftTime`，預設就是已經有
奇幻生活會員折扣（-50%）之後的時間。** 頁面最上方的「奇幻生活會員」開關預設是打開的，
這樣總製作時間、配方樹上每個分支、建議製作順序顯示的都是資料本身填的時間；如果
**取消勾選**，代表「沒有會員」，所有時間會自動 ×2 還原成一般玩家的製作時間
（製作次數不受影響，因為次數只跟每次能產出的數量有關，跟時間無關）。

這個開關的狀態會存在瀏覽器的 `localStorage`，重新整理頁面也會記得上次的設定。
